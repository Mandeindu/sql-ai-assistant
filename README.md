# 🤖 SQL AI Assistant

An AI-powered SQL assistant that allows users to interact with structured data using natural language instead of writing SQL queries manually.

The system takes a user's question, retrieves the relevant database schema using Retrieval-Augmented Generation (RAG), generates an SQL query using a Large Language Model (LLM), validates the query for safety, executes it against the database, and returns the result with insights and visualizations where applicable.

---

## 📌 Why I Built This Project

Working with databases usually requires users to understand SQL syntax, database schemas, table structures, and query logic.

For users who want to quickly explore or analyze data, writing SQL queries manually can be time-consuming and error-prone.

I built the SQL AI Assistant to make database interaction more natural:

> **Ask a question in plain English → Generate SQL → Validate → Execute → Understand the result**

The project combines Large Language Models, RAG, vector search, SQL validation, database execution, and data visualization into a single workflow.

The goal is to make data exploration easier while maintaining control over the SQL queries generated by the AI system.

---

## 🎯 Problem Statement

Traditional database analysis requires users to:

- Understand SQL syntax
- Know the database schema
- Identify the correct tables and columns
- Write SQL queries manually
- Debug SQL errors
- Analyze and interpret query results

The SQL AI Assistant automates much of this process.

Instead of writing:

```sql
SELECT product_name,
       SUM(profit) AS total_profit
FROM sales
GROUP BY product_name
ORDER BY total_profit DESC
LIMIT 1;
```
The user can simply ask:

>**Which product generated the highest profit?**

The assistant handles the SQL generation and execution workflow.

## 🛡️ SQL Validation and Safety
Generated SQL should not be executed blindly.

The project includes a dedicated SQL validation layer that checks generated queries before they are executed.

The validator helps identify and block potentially destructive SQL operations such as:
```sql
DROP
DELETE
UPDATE
INSERT
```

## 💬 Conversational Queries
The project also includes support for conversational interactions.

Instead of starting every query from scratch, users can continue exploring the same dataset through follow-up questions.

For example:
```sql
User:
Which category has the highest sales?

Assistant:
Technology.

User:
What about profit?

Assistant:
Technology generated the highest total profit.
```
This makes the interaction more natural and closer to how users normally explore data.

## 📊 Insights and Visualization
The project goes beyond generating SQL queries.

After executing a query, the resulting data can be processed to generate useful insights and visualizations.
